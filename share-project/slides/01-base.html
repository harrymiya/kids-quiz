5–12′ · 只讲够用的概念

Agent 不只是聊天，它要完成任务

把 Agent 理解成一个可以接收目标、调用工具、根据结果继续行动，并把结果交回给人的工作伙伴。

最小公式目标 → 行动 → 反馈人负责验收
先记住这一句Agent = 模型 + 上下文 + 工具 + 验证
部分它负责什么我们要做什么
🧠 模型理解问题、生成方案、决定下一步复杂任务用能力足够的模型
👁 上下文知道背景、目标、限制和已有材料把任务说清楚，资料给准确
🖐 工具读文件、搜资料、跑代码、调用系统给它合适的权限和工具
✅ 验证确认结果是否正确、可用、可交付测试、对照原文、人工确认

一个 Agent 任务的最小闭环

01给目标我想完成什么
→
02拆任务先做什么、后做什么
→
03调工具读、搜、写、跑
→
04看结果验证并继续或交付
💬 普通聊天

问一个问题，得到一段回答。适合解释、改写、总结。

🤖 Agent 工作

给一个目标，让它分步执行。适合排错、写代码、调研和整理材料。

🧑‍⚖️ 人的角色

给目标、给边界、验结果、做决策。Agent 是能力放大器，不是责任替代品。

🧭 第一性思维不要从“这个工具有什么功能”出发，要从“我要完成什么结果”出发，再倒推：需要哪些输入、步骤、工具和验收标准。
🎙 讲师提示（约 5 分钟）

“大家先不要把 Agent 想得太复杂。它就是一个能接目标、用工具、看反馈、继续完成任务的数字同事。”

“公式里最容易被忽略的是上下文和验证。模型再强，如果不知道背景，结果也可能不对；结果再像样，如果没有验证，也不能直接交付。”

“接下来我们分别讲两件事：怎样把背景给清楚，以及怎样让它真正动手做事。”
