Agent = 大脑 + 眼睛 + 手脚

这一页先用一张图说明 Agent 怎么工作，再看两种常见路线和几项设计方法。后面的内容都会从这里展开。

公式ReAct 想→做→看Harness 五件套5 模式
一个便于理解的公式 · 学术上可对应 Policy + 观察空间 + 动作空间Agent = LLM + 上下文 + 工具
直觉对应人话你用时要干嘛
🧠 大脑LLM / 策略下一步做什么选够用的模型就行，别纠结参数
👁 眼睛上下文 / 观察+历史它能看到多少背景把背景说清楚：需求、约束和例子通常会让结果更容易使用
🖐 手脚工具 / 动作接口它能动哪些系统接好工具：文件/搜索/代码/知识库

Agent 之外还有 Environment（环境）：文件、网页、API、客户现场系统。Agent 每一步都在“看环境 → 想 → 动环境”。

ReAct：想 → 做 → 看，按结果继续下一步

THINK💭 思考拆解 + 选工具
→
ACT🔧 行动调工具干活
→
OBSERVE👀 观察结果回填，再想
→
EXIT✅ 完成返回结果、无需继续，或达到停止条件
图 · ReAct 轨迹（书中多币种例子简化）要点：上下文 = 静态前缀（身份+工具说明）+ 动态轨迹（每轮追加）。工具说明或历史记录不完整时，结果可能不稳定，也更容易重复操作。

Harness：模型之外，还需要一套配合机制

生产形态Agent = Model + Harness
Harness人话你用时的动作
上下文管理信息给够写好提示词 + 接知识库（下页讲）
工具接口手脚好使命名直观、参数给例子（第 24′ 讲）
约束默认不敢乱动删库/付款/发邮件默认要你确认
验证用可复现的检查确认结果让 linter、测试和类型检查提供依据，不只看模型自己的描述
纠正出错后按规则处理设置重试和停止条件，必要时转人工
💡 一个实际提醒模型能力会覆盖一部分原来的流程，但业务规则、权限和验收标准仍需要有人负责。把这些内容整理进 Harness，有助于让流程更稳定。

两条路线：工作流 vs 自主 Agent

🛤 工作流（确定性）

步骤相对固定：核身份→查航班→付款。适合报销、发版和巡检等规则清楚的任务。很多团队可以先从这里开始。

🧭 自主 Agent（动态）

只给目标，由它根据情况选择工具。适合调研、排错和写代码等变化较多的任务，但要配停止条件和权限限制。

⚠️ 三层限制上下文层（能看什么：防注入、脱敏）→ 执行层（能干什么：分级授权、沙盒、人工确认）→ 数据层（最终能改成什么样：行级权限、校验器）。可以先从提示词和工作流做起，再根据风险考虑是否引入更高自主度。

5 个设计方法（一句话版，便于理解）

🅿️↔️🆁 提议—审核

写和审尽量分开，避免自己写完又自己确认。审核重点看产物和验证结果。

📇 渐进披露

先给目录，用到再加载详情，减少一次性放入的信息量。

📜 只增不改

记录只追加不改历史。可回放、可审计、缓存友好。

🎯 边界+保留集

改完既测“该改的”，也测“不该动的”，避免修好一处又影响另一处。

🧩 最小 diff 可回滚

尽量小步修改，每步都能单独撤销，方便定位问题和恢复。

🎙 提示词（点击展开，12′，每块约 2–3′）

公式（2′）：“可以把 Agent 先理解成大脑、眼睛和手脚。大脑是模型，眼睛是上下文，手脚是工具。模型之外，背景和工具也会影响结果，所以不一定要先换模型，也可以先把这两部分整理好。”

ReAct（3′）：“它通常是想→做→看→再决定下一步。比如算多币种收入，它先确认需要汇率，再调用换算工具，最后用计算器求和。上下文越完整，重复操作的可能性通常越低；工具说明和历史记录不完整时，就要多留意结果。”

Harness（3′）：“模型负责生成和选择，Harness 负责把信息、工具、权限、验证和纠错这些环节组织起来。实际使用中，很多问题不一定来自模型本身，也可能是权限没配、没有验收步骤，或者出错后一直重试。把这些规则提前写清楚，会更容易管理。”

路线+限制（2′）：“步骤比较固定的任务，可以先用工作流；变化比较多的任务，再考虑自主 Agent。n8n、Dify 等工具也可以按需要组合。自主程度越高，越要把它能看什么、能做什么和需要谁确认写清楚。”

五种方法（2′）：“最后记住五个方向：写审分开、按需加载、记录只追加、改动前后都测试、小步修改可回退。后面几页还会用到。”
