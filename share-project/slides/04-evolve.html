交互、评估、后训练、进化和多 Agent，每块先讲一个工作上的结论，再给一个可以尝试的动作。时间不够时，这页可以压到 4 分钟。

⏱ 7分钟只讲用人结论回查图谱 6–10 章
模块（书）一句话结论你明天怎么做
交互 (ch6)
异步/语音/ComputerUse/机器人		观察+动作空间还在扩张：异步事件、语音三范式、直接操作屏幕、具身操作。别只盯对话框：定时任务、企微/邮件网关、录屏转脚本先试点一个。
评估 (ch7)
指标/环境/数据集/Judge/归因		没有评估，就很难判断是否改进：先准备边界集和保留集，再谈优化；让 LLM 当评委时要留意偏差。给你的 Agent 准备一组重点用例，每次改完都跑一遍。样本较少时，不要轻易把差异说成稳定提升。
后训练 (ch8)
SFT/RL/奖励/蒸馏		SFT 更偏向学习示例，RL 更偏向根据反馈调整方法。GRPO/PPO 和奖励设计都与泛化有关。多数团队可以先不训练模型：先试提示词、工作流和 RAG，确实有需要时再评估微调或蒸馏。
持续进化 (ch9)
验证/四载体/双循环/睡眠学习		沉淀可以分成知识、指令、程序和参数几层；每次更新都要验证，避免新规则带来副作用。每周留一点时间复盘轨迹：把好例子整理进 Skill 或知识库，把问题用例留下来继续测试。
多 Agent (ch10)
对等/管理/去中心/A2A		分工可能带来收益，也会增加协作成本。先确认单个 Agent 已经满足需求，再考虑拆分；接口和责任要写清楚。不要一开始就把系统拆得太复杂：可以先试一个主 Agent，再按需要增加 1–2 个负责检索或执行的子 Agent。
后记 仍待解决的问题实时交互和持续学习还有不少问题需要解决；模型能力和 Agent 的使用方式也在相互影响。对使用者来说，整理上下文、权限和验证流程仍然有价值，这些经验可以随着工具变化继续复用。
图 · 先评估，再逐步调整带 * 的两块可以先放到后面，普通团队先把评估和知识、指令、程序这些基础工作做好。实际收益仍要按任务验证。

🎙 提示词（点击展开，7′，可压 4′）

交互（1′）：“Agent 不只是在对话框里问答，也可以接定时任务、语音、屏幕操作或其他设备。大家可以先挑一个低风险场景，比如定时日报、企微问答或录屏转脚本，看看是否真的方便。”

评估（2′）：“如果没有评估，很难知道改动有没有用。可以准备一组重点用例，改完就跑，既看想改的有没有变好，也看原来正常的有没有被影响。LLM 可以当辅助评委，但不要只依赖它自己的评价。”

后训练（1′）：“SFT 更像学习示例，RL 更像根据反馈调整方法。多数使用场景不需要自己训练模型，可以先按提示词→工作流→RAG→微调的顺序尝试，前面的办法不够时再评估后面的投入。”

进化+多 Agent（2′）：“可以按知识、指令、程序、参数逐步沉淀，每周抽一点时间整理好例子和问题用例。多 Agent 会增加沟通和维护成本，先把单 Agent 的流程跑顺，再看是否真的需要拆分。”

收束（1′）：“实时交互和持续学习还有不少问题没有解决。对我们来说，当前比较实用的还是把上下文、权限和验证流程整理好；这些方法以后换工具也能继续参考。接下来看看不同岗位可以从哪里开始。”
