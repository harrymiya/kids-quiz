12–18′ · 先把信息给对

结果好不好，一半取决于你怎么说

Agent 不是读心术。任务越清楚、背景越准确、验收标准越明确，结果越容易直接使用。

通用模板少而准的背景先草稿后交付

一个任务，交代五件事

要说什么一句话说明例子
目标最后要得到什么结果生成一份客户可读的排错报告
背景现在发生了什么，给哪些材料项目版本、日志、已有处理记录
约束什么不能做，时间和格式是什么不改生产数据，控制在一页内
输出希望它按什么结构返回现象 / 原因 / 步骤 / 验证结果
验收怎样判断完成了命令可执行、数据有来源、测试通过
通用任务模板请以【角色】完成【目标】。已知【背景】；遵守【约束】；输出【格式】；完成前用【验收标准】检查，并列出不确定的地方。

同一个模板，适配四类工作

🧑‍💻 开发

“先阅读项目结构，定位这个 Bug，提出方案，修改后运行相关测试，并说明改了什么。”

🚚 交付

“根据这段日志和版本信息，整理排查步骤。每一步写出验证命令，不要直接修改生产环境。”

📋 项目管理

“把会议记录整理为任务、责任人、截止时间和风险；不确定的信息单独标记。”

💼 咨询

“基于提供的资料完成行业分析，标注来源，区分事实、推断和待核实信息。”

📚 知识库和记忆重复使用的规范、案例和操作步骤可以沉淀成文档或 Skill；保留来源和版本，不要把过期内容当成事实，也不要一次塞进所有资料。
🎙 讲师提示（约 4 分钟）

“很多人觉得 Agent 不好用，第一反应是换模型。实际更常见的问题，是目标、背景和验收标准没有说清楚。”

“大家记住五项：目标、背景、约束、输出、验收。资料不需要越多越好，要少而准确。”

“这个模板可以直接套到四种岗位。接下来再加上工具，Agent 才能从写答案变成真正做事。”
