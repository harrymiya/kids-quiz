工具接得上，Agent 才能真正干活

先从低风险、可验证的工具开始：读资料、搜信息、跑脚本、改文件、生成沟通材料。重要动作始终保留人的确认。

读做验高风险先确认

工具只记三类

👁 读：获取信息

读文件、查日志、搜资料、查知识库、调用只读接口。

🖐 做：改变环境

写代码、改文件、跑命令、提交版本、更新系统。

📣 说：交付结果

生成报告、发通知、更新任务、和人协作。对外发送前要确认。

Coding Agent 的标准动作

01先读项目结构、规范、相关代码
→
02再想说明方案和影响范围
→
03后改小步修改，留下 diff
→
04必验测试、复核、可回退
操作默认做法原因
读文件、查资料、分析日志可以先放开结果容易检查，风险相对低
写代码、改文档、跑测试允许但要留痕用 Git、版本和测试保护结果
删数据、改生产、发邮件、对外承诺必须人工确认不可逆或影响外部对象
🛡 安全底线敏感数据先脱敏；权限尽量小；高风险动作先提议、再审核；结果要能测试、能追溯、能回退。工具越强，边界越要清楚。
🎙 讲师提示（约 5 分钟）

“Agent 和聊天工具的差别，在于它能不能接到真实工具。我们先不追求全自动，先让它读资料、跑测试、生成草稿。”

“开发同学记住四步：先读、再想、后改、必验。交付、项目管理和咨询也是同一套逻辑，只是工具不同。”

“安全不是最后补的一句话。能只读就不要写，能小范围就不要全量，能回退就不要不可逆；发邮件、改生产、对外承诺必须保留人工确认。”
