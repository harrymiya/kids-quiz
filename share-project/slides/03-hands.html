工具接得好，Agent 才更容易帮上忙

工具让 Agent 能读取信息、修改内容或调用系统。写代码也常用来补齐自动化环节。这一页重点看工具怎么选，以及如何把权限和验证做好。

⏱ 9分钟五类工具 · MCPCoding 七件套安全重点

五类工具（按方向记）

类方向例子用人提醒
感知环境→Agent搜索/读文件/查库/调 API从最窄只读起步，适合缓存并行；长内容要摘要+分页
执行Agent→环境跑代码/写文件/调外部 API风险通常更高，建议先从只读和低风险操作开始
协作Agent↔Agent/人子 Agent / 人工确认专业分工 + 超时降级（5分钟无响应走保守策略）
事件触发外部驱动 webhook / 定时 / 告警 第 33′ 交互章展开
用户沟通触达人企微/邮件/语音/IM 网关同上，渠道即手脚延伸
🔧 一个设计思路通用能力适合组合和探索；专用工具适合处理规则明确、风险较高的任务（付款、删数、发邮件：参数写清楚、权限尽量小、保留审计记录）。工具说明可以按新员工手册来写：名字直观、有例子、说清边界和协作方式。MCP 可以理解为一种统一接口：工具按服务器分组，接入第三方前检查描述和版本、隔离凭证，并确认展示的参数与实际执行一致。

执行安全的三个常用措施

提议—审核Sidecar 并行门控沙盒+幂等
时机事前审批 / 事后验证执行时同步检查全程提供基础隔离
看什么产物（渲染/实跑验证）只读结构化字段（如 {tool:bash, cmd:rm -rf}）进程→容器→微VM逐级硬
用人动作不可逆操作先审批；以 linter 和测试等结果为准高风险操作转人工确认，低风险检查可以并行进行venv 不是沙盒；可按需断网和设白名单；转账先查后改并防重复；发邮件保留确认步骤
☠️ 只做关键词拦截还不够即使限制了某个命令，也可能有人通过不同命令组合实现类似效果。需要结合语义判断、权限控制和沙盒。当私有数据访问 + 不可信输入 + 对外通信同时出现时，应提高审批和隔离级别；如果还有跨会话的持久记忆，也要纳入检查。

Coding Agent：通用 Agent 的内核（七件套 + 流程）

为什么这里要讲 Coding？不少交付物最终要落到文件或代码上：PPT 可以由 OOXML 生成，PDF 可以由 MD/HTML 转换，可视化和一些 GUI 操作也能用脚本固化。以 OpenClaw 为例，它把网关、研究、电脑操作和 Coding 放在一起，文件系统是重要的协作位置。

🛡 Harness 四件（Coding）验收基线（测试/CI）· 执行边界（模块/依赖/权限）· 反馈信号（lint/类型）· 回退（Git/快照）。限制条件优先于口头提醒：能用权限和代码限制的，尽量不要只依赖文档。目标清楚、结果能自动验证的任务（例如有测试的 bug 修复）通常更适合先交给工具。遇到故障，可以按 API、工具、上下文、控制流分类，记录重试次数，必要时换方案或请人处理，并设置停止条件，避免无休止地重复调用。
🎙 提示词（点击展开，9′）

工具（3′）：“工具大致分五类，先记住它们分别连接什么。通用工具方便组合，专用工具方便做限制。工具说明可以按新员工手册来写：名字直观、有例子，也说清边界。MCP 可以看成统一接口，接第三方前先检查版本和凭证。”

安全（3′）：“执行类操作风险相对更高，可以记住三个做法：重要操作先审批、执行时做检查、用沙盒和防重复机制兜底。venv 不是沙盒，仅靠关键词也覆盖不全；私有数据、不可信输入和对外通信同时出现时，要提高审核级别。发邮件和转账都建议保留确认步骤。”

Coding（3′）：“Coding 值得先讲，是因为它既能直接产出代码，也能帮助我们补齐脚本和自动化环节，结果相对容易测试。流程可以记成：先看文档，再确认设计，写完跑测试，最后复核并用 Git 留痕。优先选择目标清楚、能自动检查的任务；如果反复出错，要设置停止条件。”
